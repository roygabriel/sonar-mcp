# Acceptance Criteria

| ID | Measurable Outcome | Edge Cases | Validation Command | Evidence | Status | Notes |
|---|---|---|---|---|---|---|
| AC-01 | search_issues tool successfully queries SonarQube issues filtered by projectKey and branch (and optional types/severities) returning structured results matching API shape | Non-existent projectKey/branch returns empty array; invalid filter combos (types/severities); results > default page size; unexpected API fields ignored; zero or 500+ issues returned | `npm run test:tools -- --grep="search_issues"` | Unit test output + JSON schema match assertions; coverage report >=85% for sonarqube-client module | Pending | Role: SoftwareEngineer; Priority: High (dep risk 0.2 on config) |
| AC-02 | transition_issue tool successfully applies resolve, wontfix, or falsepositive transitions to a given issueKey with proper error handling for invalid states | Transition on already-resolved issue; non-existent issueKey; invalid transition type; permission-denied response; network timeout on POST | `npm run test:tools -- --grep="transition_issue"` | Test output with success + error-path assertions; coverage report >=85% for tools-issues module | Pending | Role: SoftwareEngineer; Priority: High (dep risk 0.1 on sonarqube-client) |
| AC-03 | All framework components (OTEL tracing, structured logging with token redaction, health checks, stdio/HTTP transports, capability exporter) function identically to reference | Missing OTEL collector endpoint; token redaction in all log levels; health check on unreachable SonarQube; stdio vs HTTP payload limits; exporter metadata mismatch | `npm run test:framework` | Trace spans exported + log redaction verification output; component parity diff report vs cruvero-mcp-k8s@dev | Pending | Role: SoftwareEngineer; Priority: Medium (core framework) |
| AC-04 | Server registers correctly with MCP gateway exposing the two new tools with accurate descriptions, JSON schemas, risk classification (read-only vs write), and hints | Gateway unavailable on startup; duplicate tool registration; schema validation failure; incorrect risk labels (read vs write); missing hints for agents | `npm run test:gateway` | Registration payload captured in logs; gateway API response confirming exact tool schemas and classifications | Pending | Role: SoftwareEngineer; Priority: Medium (dep risk 0.1 on tools-issues) |
| AC-05 | Helm chart deploys successfully to dev environment with SonarQube URL/token injected via Vault secrets; no breaking changes to existing deployment patterns | Missing Vault secret keys; malformed SonarQube URL; namespace collision; values override conflicts; upgrade from k8s reference chart | `helm lint . && helm template . --values values.dev.yaml \| kubectl apply --dry-run=client -f -` | Helm dry-run success log; deployed pod logs confirming injected URL/token (redacted); diff report vs reference chart | Pending | Role: PlatformArchitect; Priority: High (dep risk 0.3 on config) |
| AC-06 | Failure paths (invalid credentials, network errors, malformed params) return clear MCP-compatible errors without leaking secrets; E2E tests confirm behavior | Invalid token returns generic auth error; transient network errors marked retryable; malformed projectKey/branch returns 400; secrets in error messages or traces | `npm run test:error-paths` | E2E test output for all 3 failure modes; audit log confirming zero secret leakage; error shape matches MCP spec | Pending | Role: SoftwareEngineer; Priority: Medium (cross-cutting) |
| AC-07 | CI/CD pipeline produces container image, coverage meets reference threshold, and rollout to staging verifies tools are usable by downstream agents | Coverage drops below reference (80%); image build with wrong tags; staging gateway registration fails; downstream agent invocation errors | `npm run ci && ./scripts/verify-staging-rollout.sh` | CI pipeline artifacts (image digest + coverage report >= reference threshold); staging verification log with sample tool calls | Pending | Role: PlatformArchitect; Priority: Low (final validation) |
